# 蜂鸣器音乐修改汇总

## 1. 修改背景

最初尝试把 MP3 音频转换成 PCM ROM 后直接在 FPGA 内播放。这样声音更接近原音频，但数据量很大，Vivado 综合时间明显变长，片上存储资源压力也比较大。

后来改为更适合无源蜂鸣器的方案：用音符表、节拍表和方波分频器播放主旋律。这个方案不再存储完整音频采样，只保存每个音符的编号和持续时间，综合压力小很多，也更接近常见的无源蜂鸣器音乐播放代码。

## 2. 当前音乐方案

当前工程使用 `buzzer_note_player.sv` 播放三类音乐：

| 场景 | 音乐 | 播放方式 |
|:--- |:--- |:--- |
| 游戏运行 | See You Again 主旋律 | 循环播放 |
| 游戏胜利 | Can-Can / Infernal Galop | 播放一次 |
| 游戏失败 | Mario-style 失败短旋律 | 播放一次 |
| 普通碰撞 | 约 1kHz 短音 | 约 150ms |

背景音乐保留较长的主旋律版本；胜利音乐换成更欢快、识别度更高的 Can-Can；失败音乐改成短促的游戏失败风格旋律。

## 3. 主要代码改动

### 3.1 新增 `buzzer_note_player.sv`

新增文件：

```text
vivado/Obstacle_Avoidance_Car_Project/Obstacle_Avoidance_Car_Project.srcs/sources_1/new/buzzer_note_player.sv
```

该模块接口保持和原蜂鸣器播放器一致，顶层不用改游戏控制逻辑。内部实现改成：

- `NOTE_*`：音符编号。
- `*_note()`：每首歌的音符表。
- `*_units()`：每个音符持续几个基本节拍。
- `half_cycles_for_note()`：根据音符频率计算方波半周期。
- `duration_cycles()`：根据节拍长度计算音符持续时间。
- `MODE_COLLISION`：播放普通碰撞短音。
- `MODE_SONG`：播放背景、胜利或失败旋律。

播放某个音符时，模块会按下面的关系翻转 `beep_o`：

```text
half_cycles = CLK_HZ / (note_hz * 2)
```

计数到半周期就翻转一次输出，从而产生对应频率的方波。

### 3.2 顶层改为例化新播放器

修改文件：

```text
vivado/Obstacle_Avoidance_Car_Project/Obstacle_Avoidance_Car_Project.srcs/sources_1/new/obstacle_car_top.sv
```

顶层原来使用 `buzzer_player`，现在改为使用 `buzzer_note_player`。游戏核心输出的 `music_start_o`、`music_song_o`、`music_loop_o`、`collision_start_o` 等控制信号不变。

### 3.3 Vivado 工程文件更新

修改文件：

```text
vivado/Obstacle_Avoidance_Car_Project/Obstacle_Avoidance_Car_Project.xpr
```

工程 sources 中加入：

```text

```

并移除旧 PCM 播放方案相关工程项：

```text

buzzer_pcm_rom.mem
```

旧的 `buzzer_player.sv` 文件仍保留在目录中，但当前 `.xpr` 不再把它作为工程源文件使用。

## 4. 生成脚本

新增脚本：

```text
tools/generate_buzzer_note_player.py
```

这个脚本是音乐数据的源头。修改音乐时，优先改这个 Python 脚本里的旋律表，而不是手改生成后的 `buzzer_note_player.sv`。

脚本会生成：

```text
vivado/.../sources_1/new/buzzer_note_player.sv
music/note_player_preview/see_you_again_note_player_preview.wav
music/note_player_preview/cancan_win_note_player_preview.wav
music/note_player_preview/fail_note_player_preview.wav
```

重新生成命令：

```bash
python tools/generate_buzzer_note_player.py
```

还保留了一个兼容包装脚本：

```text
tools/render_buzzer_note_player_preview.py
```

它内部调用同一个生成入口，方便之后只记一个预览脚本名也能重新生成。

## 8. 后续修改建议

如果之后还想调整音乐效果，建议按这个顺序处理：

1. 在 `tools/generate_buzzer_note_player.py` 中修改对应旋律表。
2. 运行 `python tools/generate_buzzer_note_player.py`。
3. 先试听 `music/note_player_preview/` 下的 WAV。
4. 满意后再运行 Vivado 综合。

不要只改 WAV 文件，因为 WAV 不参与 FPGA 综合；也不要只手改 `buzzer_note_player.sv`，否则下次运行脚本会把手改内容覆盖。
